Implementation was approved by the user's subsequent “可以” response on 2026-09-23 after the final planning summary. Task status is `in_progress` on `task/generation-provider-config`. ## Scope and ordering

1. **Profile contract and storage:** add non-secret profile/status schemas in `src/contracts/index.ts`; add a forward-only SQLite migration in `src/storage/store.ts` for staged profile CAS, boot activation fingerprint and per-job fingerprint. Preserve all existing tables/receipts. `Store.createJobInTx` pins the boot fingerprint for manual import, capture, polling and reprocess. Read old DBs without interpreting missing job fingerprints as consent to switch.
2. **Transport cutover:** keep shared prompts/output validation in `src/providers/generation.ts`; select only `openai-compatible` or native `ollama` transport from validated profile. Extend `src/providers/support.ts` to send an optional Bearer header without duplicating timeout, redirect and error handling. Validate `/chat/completions` versus `/api/chat` final responses and usage independently. Do not change `src/providers/jev.ts` or the publication gate.
3. **Startup and API:** `src/server/config.ts` resolves defaults/server credentials and origin binding; `src/server/index.ts` loads the validated staged profile and freezes active settings before the worker starts. `src/pipeline/worker.ts` rejects mismatched/legacy unfinished jobs before external calls; `src/server/app.ts` exposes non-secret active/staged status, saves a staged profile with CAS, rejects ordinary retry after config change and keeps explicit reprocess as a new run. All existing callers use one job-creation fingerprint source.
4. **Panel:** update `web/panels/settings.ts`, `web/api.ts` and shared API/context types only as needed. Add profile controls to the existing settings surface (no fifth page); preserve unsaved drafts under polling, cross-tab revision conflicts and current provider status. Show active versus staged profile plus restart notice; never render credentials.
5. **Examples and migration:** update `.env.example`, `compose.yaml`, `README.md` and `.trellis/spec/backend/runtime-contracts.md` to describe two real adapters, loopback-only no-auth, credential-origin pinning, server restart activation, old-job explicit reprocess and old Ollama installation migration. Keep the Antigravity default and Jev unchanged. Do not deploy or modify the production data volume.
